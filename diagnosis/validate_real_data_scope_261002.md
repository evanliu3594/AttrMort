## 四、已确认的真实数据失败（起点事实）

1. **未声明的填充值 `-999`**：63% 的全球格带着填充值进入管线。`terra::NAflag()` 返回 NaN，`raster_to_grid()` 只按 NA 丢格，`validate_mortality_input()` 把负浓度当非法值（`validate = "warn"` 阻断、`"off"` 静默通过）。回填与阻断二选一，都是口径决定。
2. **端点命名不匹配**：GBD 的 `cause_name` 是全称（"Ischemic heart disease"），查表端点是短码（`ihd`）。"端点缺席"检查报 blocking，用户拿到的提示里没有到查表名的映射指引。
3. **年龄标签不匹配**：GBD 的 `"15-19 years"` / `"<5 years"` / `"95+ years"` 与查表年龄键（`"25"`、`"30"`…）不同形，`.standardize_age_key()` 对字符型原样返回，这些行**既不参与计算也不报错**——静默丢失。
4. **表内多年份重复键**：GBD 每个 `(location, age, cause)` 每年一行；`mortality()` 没有 `year` 维度。不按年过滤时 `mort_rate` 在 many-to-many 语义下扇出 → `pivot_wider()` 产生 list-col → 最终以 `invalid 'type' (list) of argument` 崩溃，堆栈与真实原因相距很远。

## 九、已知的残留观察（本次未改，供后续）

- **`dgt_conc ≠ 1` 时两张暴露栅格的 join 键会包含 `conc` 本身**：`.left_join_common()` 以 `intersect(names(x), names(y))` 为键。`conc_real` 与 `conc_cf` 若经 `raster_to_grid(dgt = dgt_conc)` 得到**字符** `conc` 列，则键为 `x, y, conc` —— 同一格上 `conc_real ≠ conc_cf`（反事实暴露）本该逐格配对，却会被当作键而互相不匹配。Lead 用小表实测：两张 key 列同为字符时 join 行数正常，但键里确实含 `conc`。正常路径（`conc_real`/`conc_cf` 以命名参数各自传入、不与彼此 join）不可达，属**加固项**而非缺陷；下一次动 `utils.R` 时值得一并收口。
- **PWRR 扇出与内存预算**：T4 实测的 26,060,703 行 / 1.39 GB / 12.4 s 与"分块不省内存只花时间"（`chunk_ages = 1` 慢 8.0×、峰值更高）说明 `R/AGENTS.md` 第七节第 1 条的分块引擎必须先把 PWRR 扫描与 `.chunk_peak_bytes()` 的常数一起重做，否则护栏会给出错误的预算。
